#+TITLE: Changelog

All notable changes to this project will be documented in this file.

* 0.0.5 (unreleased)

** Fixed

- ~slack-open-url~ opens links it used to refuse.  A link naming a room
  rather than a message (no =/p<timestamp>= part) now opens the room;
  ~slack-permalink-to-info~ parses it with a nil =:ts= and returns nil
  for anything that is not a Slack link, instead of reading whatever the
  previous match left behind.  An enterprise grid link, whose host is
  =<organization>.enterprise.slack.com=, no longer fails the workspace
  lookup: ~slack-permalink-team~ falls back to the team that knows the
  room, then to the only registered team, and asks only when it has to.
  A room emacs-slack has not loaded, an archived channel for instance,
  is fetched with conversations.info (~slack-room-find-or-fetch~) rather
  than reported as not found.  Clicking a channel link in a message now
  opens it in emacs-slack too.  ~slack-org-link.el~ shares the one
  parser instead of keeping a second, stricter regexp.
- Message links and buttons whose URL is a Slack permalink (mrkdwn and
  rich-text links, Block Kit buttons, legacy attachment buttons, e.g. the
  ~Request~ link some bots post) open in emacs-slack instead of the system
  browser.  Their URLs are now handed to ~slack-open-url-or-browse-url~,
  which sends ~*.slack.com/archives/...~ permalinks to ~slack-open-url~
  and leaves every other URL, and permalinks of teams not registered in
  emacs-slack, to ~browse-url~.
- The test suite is green again: the sync-suggestion tests had failed ever
  since the feature landed because they assumed the feature enabled while
  ~slack-thread-suggest-sync~ defaults to nil, and checked a threshold
  boundary of 20 while ~slack-thread-suggest-sync-threshold~ is 10.  They
  now enable the feature explicitly and check the actual boundary.
- ~slack-buffer-function~ and ~slack-completing-read-function~ now carry
  their intended defaults (~switch-to-buffer~, ~completing-read~).  They
  were bare ~defvar~ declarations, which byte-compile to nothing: loading
  the compiled modules left both variables void at runtime, and
  let-binding them from a lexically-bound file did not reach the code
  using them (surfaced by the test suite's new ~lexical-binding~ cookie).

** Added

- ~slack-channel-select-archived~ lists a team's archived channels and
  opens the selected one.  Archived channels count as hidden rooms, so
  the regular selection leaves them out, and they are not part of the
  room list emacs-slack keeps (see ~slack-exclude-archived-channels~):
  the command fetches them first, with
  ~slack-channel-list-update-archived~, and they stay available for the
  session afterwards.  ~slack-conversations-list~ takes an
  =include-archived= argument for this, applied to every page of the
  listing.
- Starred (saved for later) messages are highlighted in message, thread
  and search buffers with the new ~slack-starred-message-face~, a pale
  amber wash (light and dark variants) applied on top of the existing
  per-message faces, so saved messages stand out while scrolling.  The
  saved for later buffer itself does not highlight, since every message
  there is saved; ~slack-highlight-starred-messages~ turns the highlight
  off everywhere.  The state comes from the team's saved for later list,
  now fetched when a team connects: ~conversations.history~ stopped
  carrying ~is_starred~ when saved items replaced stars, so the message
  payload alone cannot tell whether a message was saved.
- The stars buffer binds =g= to ~slack-stars-refresh-buffer~ in addition
  to =G=.
- ~slack-emoji-dwim~ runs the emoji command the cursor asks for: on a
  message it adds the selected emoji as a reaction
  (~slack-message-add-reaction~), while typing it inserts it at point
  (~slack-insert-emoji~), in the input area as well as in a compose or
  edit buffer.  One key can take the place of the two commands, which
  stay available on their own.

** Changed

- Starring or unstarring a message now logs the outcome at info level
  (~Successfully starred message.~ / ~Successfully unstarred message.~)
  once the API confirms it, so the change is not silent: the message's
  saved state is also updated locally and its buffers redrawn right away
  (the star RTM events this used to rely on are legacy).  Removing a star
  from the stars buffer deletes its line as soon as the removal is
  confirmed instead of waiting for the next refresh.
- ~slack-block.el~ split into per-concern modules: ~slack-block-util.el~,
  ~slack-block-composition.el~, ~slack-block-element.el~,
  ~slack-block-rich-text-element.el~, ~slack-block-rich-text.el~,
  ~slack-block-layout.el~, ~slack-block-plan.el~, ~slack-block-table.el~,
  ~slack-block-timeline.el~, and ~slack-block-video.el~.  ~slack-block.el~
  remains the umbrella entry point and still provides ~slack-block~, so
  =(require 'slack-block)= keeps working unchanged.

* 0.0.4 (unreleased)

** Fixed

- Timestamps like ~17:00:00~ render as plain text again.  Workspaces with
  numerically named emoji (~:00:~, ~:100:~, ~:404:~, ...) made emojify
  substitute the ~:00:' embedded in every timestamp, duration and version
  number once the workspace emoji list was synced into
  ~emojify-user-emojis~.  emojify is now advised (in slack buffers only) to
  substitute a shortcode only when it stands on its own, the same rule the
  Slack app applies; see ~slack-emoji-shortcode-standalone-p~.
- Saved-for-later items that only exist as thread replies now resolve: the
  channel history call cannot see them and used to answer with the nearest
  older message, leaving the ~(loading message...)~ placeholder behind (and,
  before the async conversion, silently rendering the wrong message).
  ~slack-message-get-or-fetch-async~ now detects the timestamp mismatch and
  anchors a second ~conversations.replies~ call at the requested timestamp,
  which Slack resolves to the reply itself.  A fetch that finds nothing
  replaces the placeholder with the shared
  ~slack-unavailable-message-string~ notice instead of waiting forever.

** Changed

- The saved-for-later (stars) buffer is fully non-blocking: saved messages
  render as placeholders that are filled in as the fetches complete.  The
  placeholder text is the shared ~slack-loading-message-string~ defcustom,
  now also used by the activity feed.  The blocking
  ~slack-message-get-or-fetch~ has been removed; use
  ~slack-message-get-or-fetch-async~ instead.
- ~slack-search-query-params~, ~slack-search-from-messages~ and
  ~slack-search-from-files~ now accept optional =team=, =sort= and
  =sort-dir= arguments (in addition to =query=); nil values still fall
  back to the interactive prompts.  This lets callers bind static
  searches to keys without going through the minibuffer.

** Added

- Sync suggestion in thread buffers (~slack-thread-suggest-sync~, off by
  default): when a thread is longer than
  ~slack-thread-suggest-sync-threshold~ messages (default 10) and the most
  recent ones alternate between two or three people, the buffer shows a
  one-time hint that a quick sync might resolve things faster.
- VIP / priority user support: golden =[VIP]= badge, add/remove commands
  (~slack-vip-add~ / ~slack-vip-remove~), filtering in message headers,
  @mentions, Block Kit, and profile buffers
- Activity feed views: filter by all, unreads, VIP, VIP unreads, threads,
  threads unreads, mentions unreads, and starred (~slack-activity-feed-show~,
  ~slack-activity-feed-switch-view~ bound to =v=)
- Non-blocking activity feed: lazy async message body population with
  ~(loading message...)~ placeholders replaced on fetch completion
- Group / MPIM creation from an IM buffer: pre-populate with current DM users
  and add more (~slack-group-mpim-open-from-current~)
- Draft-then-send file upload flow: attach files to the draft with =C-c C-f=
  (~slack-file-attach~), review with ~slack-file-attach-list~, clear with
  ~slack-file-attach-clear~; files upload on send, mirroring the Slack app
- Visual overlay showing queued files with clickable remove buttons above the
  prompt
- ~yank-media~ handler for clipboard images (Emacs 29+): pasted images are
  queued to the draft automatically
- ~text/uri-list~ handler for file-manager copies: image files copied from a
  file manager are queued to the draft via ~yank-media~
- Drag-and-drop queues files to the draft instead of uploading immediately
- Gap markers in channel buffers to load older messages bidirectionally
  (~slack-buffer-fill-gap~)
- Export capabilities for Slack buffers (~slack-export~)
- Block Kit support: layout header, plan, table, timeline, citation, video,
  canvas, message_mention, attachment_mention, and rich-text blocks
- Saved for later / starred messages support with actions in the star buffer
- Scheduled messages management
- Remind for later support (~slack-reminder.el~ cleanup)
- User status reset and expiration
- Usergroup users list and update
- Muted channels parsing (~users.prefs.get~)
- Snippet preview in file upload
- Rounded corners for images using SVG clip-path
- Opening original images by clicking on image preview
- Kill URLs hidden behind a button with =w= key
- Fetch users not loaded at startup
- Active status / presence icon on user selection when mentioning
- Option to ignore Slack previews
- File download location prompt, streamlined UX, and error surfacing
- Curl options for request.el (~slack-request-curl-options~)
- Activity feed debugging facility
- Default team on ~slack-start~
- Pagination and resilience for activity feed
- Present-in active icon
- Non-blocking full image opening: ~slack-image-open-at-point~ downloads the
  file asynchronously (showing "Downloading image ..." while it transfers) and
  opens it only when the download completes
- Option to open images in the system default image viewer:
  ~slack-image-open-externally~ opens with ~xdg-open~ / ~open~ / ~cmd start~
  instead of an Emacs buffer; a prefix argument (=C-u RET= / =C-u mouse-1= on
  the thumbnail) inverts it per invocation
- Org links to Slack messages (~slack-org-link.el~): the =emacs-slack:= Org
  link type now uses Slack permalinks as its address, so following it opens
  the message in emacs-slack and falls back to the browser when the team or
  room is not available; ~org-store-link~ works in message, thread, search
  result and pinned item buffers; export emits real https permalinks; typing
  a link completes over the connected teams' rooms; the
  TEAMID[&|]ROOMID[&|]ts:TS format stored by the ol-emacs-slack package is
  still understood, with the old ~ol/...~ function names kept as obsolete
  aliases.  Adds a reusable ~slack-team-domain~ helper on ~slack-team.el~
- Optional alert style capturing message alerts as Org TODO headings
  (~slack-org-alert.el~): ~slack-org-alert-setup~ registers the style and
  ~slack-org-alert-file~ enables capture; captured headings carry a permalink
  link and the ~slack-org-alert-tag~ tag (kept separate from the heading
  format so customizing it does not break agenda actions); duplicates and
  alerts without message identity are skipped; ~slack-org-agenda-mark-all-done~
  marks all tagged agenda entries done
